# eng-protocol

在每次模型请求前，用少量当前有用的工程规则帮助模型校准下一段回答和行动。

前面的内容会影响后续生成。错误假设、过时计划和偏离任务的思路，也可能被不断沿用。本插件根据已有对话和工具证据选择提醒；目标是改善实际结果，同时减少无必要的提醒、请示和流程。

## 工作方式

1. `before_agent_start` 将 `protocol.md`、简短计划要求和可选项目规则放入系统提示段。
2. `context_with_system` 在下一次模型请求前构建有界的决策上下文。
3. 决策模型分别评估规则的当前状态，以及规则之间的条件关系；每批最多 16 个问题，最多两批同时请求。
4. 对“需要处理”概率达到 0.6 且为唯一最高选项的规则，处理覆盖、阻塞和前置关系，再选取至多 3 张卡片，以 `<engineering-guidance>` 附在本次请求末尾。允许不选任何卡；提醒不写回会话记录。

插件保持模型的行动自主性。它的干预点是模型请求之间；同一次回复中的计划和工具调用之间没有额外干预点。计划是后续请求的参考线索，不能保证提前观察到每个动作。

## 决策上下文

- 最新用户消息单独标记；它可能是新任务、补充或修正。
- 之前的用户原话按总字符预算保留，最近工具窗口跨越用户消息边界。
- 用户消息、计划、最新回复和工具结果带有消息位置，供决策模型判断先后及是否过时。
- 长文本保留首尾；决策状态标明省略的用户消息与工具调用数量。缺少记录不等于没有做过。
- 项目规则以有界摘录提供给决策模型，主模型接收完整项目规则。

当前预算：最新请求 2000 字符；用户历史 3000 字符（含记录开销，单条最多 1000）；最近 10 次工具调用，每次参数和输出各最多 600；最新回复 800；计划 600；可用思考内容末尾 1500；项目规则 1500。超出预算或已被宿主压缩的历史可能不可见，插件不提供持久化任务记忆。

当前有 27 张卡片和 5 条条件关系，共 32 个问题、2 个 HTTP 请求。规则包括事实核验、外部调研与方案适配、调用影响、授权、任务边界、实现设计、超时取消、并发、外部输入、兼容迁移、架构、UI、验收、交付、验证范围、信任边界、来源核对和执行进展。16 是 [SubQ 单次请求问题上限](https://docs.subq.ai/endpoints/decisions-api/)，卡库可继续扩展；关系问题同样计入上限。

每张卡使用五种状态：需要处理、正在处理、已满足、不适用、证据不足。状态是决策模型对当前证据快照的判断，不是经过证明的事实或永久完成标记。相关代码或契约改变后重新评估，已发送提醒不算完成；可见历史的摘要哈希让摘录范围外的变化也能使缓存失效。哈希不能恢复被截断的证据，缺少记录仍应判为未知。

关系图定义有明确含义的有向边，并在请求前检查重复 ID、失效引用和循环。每条关系条件单独评估，只有同一具体义务的条件明确成立才参与筛选：具体提醒覆盖重复提醒；真实待决事项阻塞依赖它的继续工作；冲突契约未解决时推迟相应验收提醒。无关义务、未知关系和未入选的覆盖来源不会机械压掉卡片。所有卡都参与评估，图不截断候选范围，也不传播或放大概率。

“外部调研与方案适配”同时写入常驻规范与动态卡片。关键技术选择、陌生或易变接口、争议结论应查官方文档、原始论文或成熟实现，比较方案并核对逻辑、版本、成本和应用场景。已有充分依据、正在调研、普通修改或用户禁止联网时不催促重复搜索。

2026 年模型问题的改造依据见 [研究与规则映射](research/model-failures-2026.md)和[来源登记](research/model-failures-2026.json)。每张相关卡的 `evidence` 字段引用登记项，保留被观察模型、来源类型、日期与限制；不把旧版本或关闭防护的实验外推成所有模型的通病。这些审计元数据不发送到决策提示中。触发依赖当前行为证据，不依赖模型名称；提醒不能替代权限隔离或保证不再犯错。

## 配置

全局 `~/.pi/agent/eng-protocol.json`：

```json
{
  "enabled": true,
  "maxCards": 3,
  "minProbability": 0.6,
  "sendReasoning": true,
  "decision": {
    "endpoint": "https://api.subq.ai/v1/systemone",
    "model": "subq-snap-preview",
    "apiKey": "$SUBQ_API_KEY",
    "timeoutMs": 4000
  }
}
```

`apiKey` 支持字面值、`$VAR` / `${VAR}` 环境变量和 `!命令` 的标准输出。命令在加载或重载配置时执行，输出不写入评测记录。

项目 `<repo>/.pi/eng-protocol.json` 可覆盖除 `decision` 以外的字段；决策服务地址与取密钥命令只来自全局配置。项目规则放在 `<repo>/.pi/eng-protocol.md`。

- `/protocol status`：查看开关、决策服务和最近状态。
- `/protocol on` / `off`：本会话启用或停用。
- `/protocol reload`：重载 `protocol.md`、配置、决策源、项目规则和架构索引，并清空决策缓存。规范与项目规则用于下一次代理运行的系统提示。
- `/protocol show`：查看每条规则的状态、P(需要处理)、选择或压制原因、成立的关系、问题与请求数量，以及实际注入的文本。

完全相同的决策状态可复用成功结果。各批次共用同一个总超时和取消信号；任一批次失败或响应不完整时取消其余批次，丢弃部分结果。新上下文会取代仍在等待的旧决策；停用、重载或结束会话也会取消等待，旧结果不会回写缓存或注入后续请求。决策超时或失败时跳过本次动态提醒，常驻规范仍然有效；主动取消不作为服务故障告警。默认阈值和卡片上限是待校准的起点，五分类概率不能视为旧二分类分数的等价替换。

发送给决策服务的内容包括上述用户原话、项目规则摘录、工具参数与输出、计划及可用思考内容，以及可见历史的哈希。`sendReasoning: false` 可关闭思考内容发送。每次未命中缓存会执行全部批次，卡片和关系数量增加会增加请求与费用；并发不代表费用减少。加载本插件的子代理也有这一开销。

## 开发与验证

`guidance.ts` 负责纯函数核心，`decision.ts` 负责 HTTP，`index.ts` 负责 Pi 事件。运行时不增加第三方依赖。

```powershell
node --test guidance.test.ts decision.test.mjs index.test.mjs eval/checks.test.mjs
D:/Myproject/SoL-Pi/node_modules/.bin/tsc -p tsconfig.json
```

类型检查路径沿用本机 Pi 安装配置。测试覆盖有界上下文、状态分布解析、关系覆盖与独立义务、前置条件、跨批次并发与失败、缓存失效、重载、超时和取消、会话关闭、消息不变性、实际注入展示和评测判分。HTTP 与生命周期测试使用本地服务；这些测试验证程序行为，不能证明模型分类正确。

## 模型评测

`eval/` 保留短任务与长会话对照。`static` 和 `plugin` 使用同一份规范、同一计划要求和相同系统提示段；只有插件组进行动态选卡。`none` 不加载工程规范。

```powershell
node eval/fixtures.mjs
$env:RUNS_DIR = 'runs-example'
$env:ARMS = 'static,plugin'
$env:TASKS = 't1_signature,t3_dependency,t4_conflict,t6_removal'
node eval/run.mjs 2 2
node eval/score.mjs | node eval/summary.mjs
node eval/routing.mjs
```

运行会调用已配置的模型服务并产生费用。使用新的 `RUNS_DIR` 保持实验隔离；`fixtures.mjs` 重建 `eval/fixtures` 内的测试仓库。`PI_CLI`、`EVAL_MODEL` 可覆盖 CLI 路径和模型。长会话使用 `eval/long/run.mjs`、`eval/long/score.mjs`，其 `RUNS_DIR` 相对于 `eval/long`，`MAX_TURNS` 可限制轮数。

评测以功能和任务边界为主：独立验收检查实际行为，模型写的测试作为补充；验证指标关联工具完成结果，无法识别的命令或退出码标为未知。复合 shell 命令保守处理。发生超时或模型错误的任务不能算成功。冲突任务的自动检查只确认保留代码与断言并给出回复，解释是否正确仍须人工复核。

每次实验记录代码及提示词摘要、模型、Node 版本和不含密钥的有效配置。输出 token 与可用的主模型费用单独报告；价格缺失时标未知，决策费用未计入主模型费用。报告标题和风格关键词不作为质量得分。

`routing.mjs` 用合成会话比较当前代码与 `BASELINE_REF`（默认 `HEAD`）的选卡边界；也可用 `BASELINE_FILE` 指向保存的 `guidance.ts`。输出记录基线源码摘要，基线没有的必选卡标为不可比较。当前版还复用同一批概率生成 `candidate-flat`，比较相同卡片与状态下启用和关闭关系约束的选择；这不隔离五状态判断本身的效果，也没有额外调用费用。服务失败记录为失败，不静默跳过。

场景包括根因核验、独立验收、部分完成、验证后再次修改，以及已在调研、证据充分、用户禁止联网等边界。`CASE_IDS` 可指定逗号分隔的场景，`ROUTING_ARMS=baseline,candidate` 可选择版本。`CASE_FILE=eval/replay-cases-20261016.json` 可回放已冻结的模型执行记录，结果保存场景摘要。记录来自合成工程任务中的实际模型执行，不是生产会话。它只调用决策服务，检查指定的必选、排除或空结果，不是全部卡片的精确率标注或独立泛化评测。

2026 年来源对应的正反例由 `node eval/model-failures-cases.mjs` 生成。设置 `CASE_FILE=eval/model-failures-cases-20261016.json` 后运行 `routing.mjs`，可以检查重复验证、已授权工作、答案污染、夹带指令、记忆污染、虚假来源和进展更新边界。这些是根据机制设计的合成诊断场景，不能冒充原报告的模型实测记录。

已保存的历史结果反映当时的实现和判分规则，不直接证明当前版本效果。小样本用于发现回归，不能据此宣称普遍提升。

模型问题对应卡片的检查与限制见 [2026 模型问题验证](eval/validation-model-failures-2026-10-16.md)，决策机制见 [规则状态、关系与分批决策验证](eval/validation-graph-2026-10-16.md)。历史版本见 [2026-10-15 验证记录](eval/validation-2026-10-15.md)和 [2026-10-16 提醒边界验证](eval/validation-2026-10-16.md)。
